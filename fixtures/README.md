# Fixtures

Short golf clips plus hand-labelled ball positions. `npm run eval` runs the tracking
pipeline over every fixture and prints a comparison table. The full protocol (coordinate
conventions, metrics, pass/fail thresholds) is in [docs/TESTING.md](../docs/TESTING.md).

## Layout

```
fixtures/
  truth.schema.json        JSON Schema for truth.json (editors pick it up via "$schema")
  example/truth.json       format example, no video
  real/<clip-id>/          your footage — one directory per clip
    clip.mov               the video (gitignored, never committed)
    truth.json             labels (committed)
  synthetic/               generated by the synthetic-fixture tool (M1), gitignored
```

## Adding a real clip

1. Pick a descriptive id: `<view>-<mount>-<background>-<nn>`, e.g. `dtl-tripod-sky-01`.
2. Trim to the shot — roughly 1 s before impact until the ball is gone. Stream copy keeps
   the original encode (the start snaps to the previous keyframe, which is fine):

   ```sh
   ffmpeg -ss 00:00:03.2 -i IMG_1234.MOV -t 5 -c copy -map 0 fixtures/real/dtl-tripod-sky-01/clip.mov
   ```

3. Label it with the labelling tool (milestone M1), or write `truth.json` by hand against
   the schema. Record the SHA-256 so labels stay tied to one encode:

   ```sh
   sha256sum fixtures/real/dtl-tripod-sky-01/clip.mov
   ```

4. `npm run eval` validates every `truth.json` and tells you whether the clip is present.

Clips are large, so they live outside git. Keep your originals somewhere safe. The
`sha256` in each `truth.json` is how the harness notices that a clip was swapped out
from under its labels.

**iPhone footage:** AirDrop or copy the file from the Files app. Anything that goes
through the Photos picker or a messenger app gets re-encoded (often down to 720p), and
that is not what the app will see from users who pick "from Files".
