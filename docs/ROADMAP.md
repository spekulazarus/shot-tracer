# Roadmap

Every milestone ends in something you can **see** — a video, a table, a URL on your phone.
Risk goes first, measurement comes before tuning, and the product is usable (via manual
mode) before automatic tracking is perfect.

| | Milestone | Demo | Depends on |
| --- | --- | --- | --- |
| **M0** | Walking skeleton on a real iPhone | Pick a 4K60 clip on iPhone → get it back with a dummy line and audio, saved to Photos. Go/no-go report. | — |
| **M1** | Measurement: fixtures, labelling, eval harness | `npm run eval` prints the comparison table over synthetic and real clips | — (M0 for the labelling tool) |
| **M2** | Detection on tripod footage (steps 2–3) | Overlay video of candidate blobs; candidate recall per fixture | M1 |
| **M3** | Stabilization (step 1) | Side-by-side original vs. stabilized handheld clip; stab residual on synthetic shake | M2 |
| **M4** | Trajectory fit (step 4) | First real recall/error numbers; fitted curve + inliers overlaid on fixtures | M3 |
| **M5** | First traced video (step 7 + export) | In the browser, incl. iPhone: clip in → traced MP4 out, trace locked to the ball on handheld footage | M0, M4 |
| **M6** | Editor & manual mode | Fix a failed clip by hand in under a minute; trace a clip with zero detections | M5 |
| **M7** | Refinement & ball loss (steps 5–6) | Eval deltas vs. the M4 baseline: recall up, launch Δ down; tails reaching labelled landings | M4 (M6 for the landing tap) |
| **M8** | PWA shell | Install to the iPhone home screen, airplane mode, trace a clip | M5 |
| **M9** | v1.0 release | Public URL; README accuracy table generated by the harness | all |

M0 and M1 are independent and can run in parallel. M0 needs a real iPhone; M1 needs
footage.

## Changes from the brief's proposed order, and why

The brief suggested: blob detection → stabilization → RANSAC → rendering → editing UI → PWA
shell → deploy. That order is kept for the tracker itself. The changes:

1. **M0 walking skeleton comes first.** The riskiest assumption in the whole plan is that
   iOS Safari can decode 4K60 HEVC, encode it back, and stream 300 MB files without the tab
   being killed. Four milestones of CV work built on top of an unverified assumption would be
   expensive to throw away.
2. **Deploy moves from last to M0.** WebCodecs, OPFS and service workers require HTTPS, and
   the phone is where the footage is. A preview URL per branch is how every later milestone
   gets tested on a real device, not a release chore.
3. **The eval harness gets its own milestone (M1), before any detection code**, so that
   steps 2–3 are measured from their first commit rather than eyeballed.
4. **Rendering and export (M5) come before Kalman refinement (M7).** The first end-to-end
   traced video should exist as early as possible. Refinement is then a measured improvement
   on top of a working product, not a prerequisite.
5. **The editor (M6) also comes before refinement.** With handheld-against-trees working
   about half the time, manual correction delivers more user value per hour than squeezing
   the Kalman stage, and manual mode makes the app useful even when detection fails
   completely. The landing tap (step 6) naturally belongs to the editor.

## M0 — Walking skeleton on a real iPhone

**Goal:** prove (or disprove) the platform assumptions under ADRs 0001–0003 on the
target device, and give every later milestone an HTTPS URL to test on.

**Demo:** open the preview URL on an iPhone → pick a 4K60 HEVC clip from Files → get back
an MP4 with a static diagonal line burnt into every frame and the original audio intact →
Share → Save Video. Plus a capability page that reports what the device supports.

**Done when** `docs/spikes/m0-ios.md` records, for at least one recent and one older iPhone:
decode of 4K60 HEVC (SDR and HDR) ✓/✗ and speed; H.264 encode at 4K and 1080p ✓/✗ and
speed; peak memory; OPFS streaming of a 300 MB output ✓/✗; share sheet ✓/✗; OpenCV.js load
time and memory in a worker. **Any ✗ goes to the project owner before M2 starts.**

Issues:
1. Capability probe page
2. Deploy pipeline: Cloudflare Workers static assets, previews per branch
3. Decode spike: Mediabunny + WebCodecs in a worker
4. Analysis frames: `VideoFrame` → grayscale buffer at analysis resolution
5. Encode + mux spike: burn in a line, H.264, audio passthrough, stream to OPFS
6. Save/share the output + Photos-picker 720p detection
7. OpenCV.js 4.12 in a worker: lazy load, smoke test, memory
8. iPhone feasibility report (go/no-go)

## M1 — Measurement: fixtures, labelling, eval harness

**Goal:** the harness from [TESTING.md](TESTING.md) exists and every later change is
judged by it.

**Demo:** `npm run eval` prints the full table (recall, errors, PASS/FAIL, Δ vs. baseline)
over the synthetic set and the owner's first real clips — with a stub tracker that finds
nothing, so the numbers are honest zeros. CI runs the synthetic set with `--strict`.

**Done when:** metrics are unit-tested; at least 6 real clips are labelled across view ×
mount × background; the synthetic set covers face-on, down-the-line and camera shake.

Issues:
1. Core types, `PipelineConfig` and the `FrameSource` interface; DOM-free tsconfig for `core/` + `geometry/`
2. Node `FrameSource` via ffmpeg
3. Metrics module
4. Eval CLI v1: table, JSON report, baseline compare/save, `--strict`
5. Synthetic fixture generator + CI job
6. Labelling tool (dev-only page)
7. Label the first real fixtures

## M2 — Detection on tripod footage (steps 2–3)

**Goal:** frame differencing and candidate filtering on footage that needs no stabilization.

**Demo:** overlay video of each frame's candidates on a tripod clip; eval shows candidate
recall.

**Done when:** candidate recall ≥ 0.9 on tripod/sky fixtures; candidates per frame reported;
all thresholds in `PipelineConfig` and overridable from the eval CLI.

Outline: `CvBackend` wrapper + Mat lifetime helper · motion extraction · candidate filter
(area, circularity with small-blob exemption, contrast polarity switch) · candidate overlay
in `--debug-video` · harness column `cand`.

## M3 — Stabilization (step 1)

**Demo:** a handheld clip, original vs. stabilized, side by side; synthetic shake clips
report stab residual.

**Done when:** stab residual < 0.5 px@1080 on synthetic shake; `A_n` persisted per frame;
false candidates on handheld fixtures drop measurably, with no loss of candidate recall.

Outline: similarity RANSAC estimator in `geometry/` (unit-tested against known transforms)
· LK tracking with forward-backward check on a lower-two-thirds mask · transform chain and
unreliable-frame flags · warp-before-diff integration.

## M4 — Trajectory fit (step 4)

**Demo:** eval table with the first meaningful recall and error numbers; debug video with
the fitted curve, inliers and rejected candidates.

**Done when:** tripod/sky pass rate ≥ 80 %; results deterministic across runs; the first
baseline is committed.

Outline: per-frame candidate grid · seeded parametric RANSAC (ADR 0006) with plausibility
priors · longest coherent run scoring · LS refit, optional cubic · top-k alternative
hypotheses.

## M5 — First traced video (step 7 + export)

**Demo:** in the browser — on an iPhone too — pick a clip → automatic trace → export an MP4
where the line grows with the ball and stays locked to it while the camera moves.

**Done when:** the round-trip invariant test (`R → S_n → R`) exists; the on-device
checklist passes; the export matches source resolution/fps, or explains the 1080p fallback.

Outline: analysis worker wiring the browser `FrameSource` to `core/` · Catmull–Rom spline
with time parametrization · shared render function (preview + export) · export worker
(decode → draw → encode → mux → OPFS) · progress and cancellation UI.

## M6 — Editor & manual mode

**Demo:** take a clip where automatic tracking failed and fix it by hand in under a minute;
trace a clip in manual mode with detection skipped entirely.

**Done when:** add/move/delete control points; apex/shape handle; set impact and landing;
switch hypothesis; reset; unlimited-feeling undo/redo (200 steps); touch + mouse +
keyboard; manual mode works with zero detections.

Outline: `TrackDocument` + snapshot history in `editor/` (unit-tested) · exact-frame
scrubbing preview · overlay hit-testing through `A_n` · manual-mode seeding · landing tap.

## M7 — Refinement & ball loss (steps 5–6)

**Demo:** eval deltas against the M4 baseline — recall up, launch Δ down, no regressions;
extrapolated tails that reach labelled landing points.

**Done when:** constant-acceleration Kalman + RTS smoother · pass B windowed re-detection
(±15 px, relaxed thresholds) · gap interpolation · extrapolation with and without a
landing constraint · landing-error metric reported.

## M8 — PWA shell

**Demo:** add to the iPhone home screen, switch to airplane mode, trace and export a clip.

**Done when:** app shell + OpenCV.js precached; update prompt; `storage.persist()`;
manifest, icons and iOS meta tags; offline behaviour covered by the on-device checklist.

## M9 — v1.0 release

**Done when:** production deploy on the final domain; the README accuracy table is
generated from `npm run eval` over the fixture set; the on-device checklist passes on two
iPhones (one older); known limitations are documented honestly.

## Backlog (unscheduled until data says so)

- Custom slim OpenCV.js build with SIMD (ADR 0003) — when M0/M5 measurements show
  load time, memory or speed problems.
- WebGPU accelerator for downscale/diff/composite (ADR 0008) — when device measurements
  miss the targets and parity holds.
- HDR-aware export (tone-mapping or HEVC Main10), depending on the M0 findings.
- Playwright browser-vs-Node parity job (ADR 0009).
- Phase 2: TrackNet-style detector via onnxruntime-web; LLM-assisted cosmetics; batch
  processing, 4K export presets, share flows.
